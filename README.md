# control-tower

Claude Code mod providing a control tower dashboard for Claude Code sessions.
The mod lives in `control-tower/`.

## Development

Always develop against the working copy, never against the installed copy:

```sh
claude --plugin-dir ./control-tower
```

## Checks

Run from the repository root:

```sh
claude plugin validate --strict control-tower
scripts/check-calls.sh control-tower
claude plugin test control-tower
```

`scripts/check-calls.sh` fails when the mod calls `$` outside
`fs`, `process`, `clock`, `ui`, `tool` and `state`.

### `scripts/check-calls.sh <mod-dir>`

`claude plugin validate` reports the `$` calls of each module but does not
refuse any noun, hence this guard. It reads `claude plugin validate --json`
(requires `jq`) and exits with:

- `0` when every `$.<noun>` call is allowed, or when the mod calls nothing on `$`;
- `1` with the forbidden calls listed on stdout (e.g. `$.http.fetch`);
- `1` when `validate` fails (missing directory, invalid mod): stderr gets
  `validate failed: <mod-dir>` followed by validate's error messages, one per
  line; stdout stays empty;
- `2` without exactly one argument (usage on stderr).

Its own test, which builds throwaway mods in `$TMPDIR` and removes them on exit:

```sh
scripts/check-calls.test.sh
```

## Layout

- `control-tower/.claude-plugin/plugin.json`: manifest (`--strict` requires `author`).
- `control-tower/hooks/hooks.json`: declares the hook module `./register.ts`.
- `control-tower/hooks/register.ts`: registers `session.start`, which currently
  passes the event through unchanged.
- `control-tower/hooks/register.test.ts`: run by `claude plugin test`.
- `control-tower/.claude-plugin/types/`: types generated by the engine, git-ignored.

## Constraints

Mod code uses no `setTimeout`, `fetch` or Node API: only `$.clock`, `$.fs`,
`$.process` (and the other allowed `$` nouns). The types generated in
`control-tower/.claude-plugin/types/` are the reference. This rule is not
checked automatically beyond `scripts/check-calls.sh`.
